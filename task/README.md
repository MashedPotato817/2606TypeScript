# TypeScript 任务书

目标：给 Python 智能体做一个网页任务面板。

按顺序完成，每次只做一个任务。前 5 个练习放在 `ts/`，页面项目放在 `task/agent-panel/`。

从 [任务 1：消息列表跟做指南](01-message.md) 开始。

| 完成 | 任务 | 学什么 | 完成标准 |
| --- | --- | --- | --- |
| [ ] | 1. 消息列表：定义消息，添加消息，筛选用户消息 | 对象类型、字面量联合、类型推断 | 角色只能是 `user/assistant/system`，拼错会报类型错误 |
| [ ] | 2. 任务状态：定义等待、运行、成功、失败 | 联合类型、类型收窄、`never` | 成功必须有结果，失败必须有错误；新增状态能发现遗漏分支 |
| [ ] | 3. 读取 JSON：检查模拟后端数据 | `unknown`、运行时校验 | 合法数据能读取，缺字段或字段类型错误能拒绝 |
| [ ] | 4. 通用结果：定义 `Result<T>`，用于消息和任务 | 泛型 | 同一结果结构能保留不同数据类型，不用 `any` |
| [ ] | 5. 智能体配置：定义配置和配置更新参数 | `keyof`、`Partial`、`satisfies` | 配置键拼错或值类型错误会报错；更新类型从配置类型派生 |
| [ ] | 6. 网页面板：输入问题，提交，显示状态和模拟回复 | DOM、事件、`async/await` | 浏览器能完成一次模拟任务，展示成功和失败 |
| [ ] | 7. 接入 Python：把模拟请求换成真实请求 | `fetch`、接口契约、数据校验 | 网页能调用智能体，并处理请求失败和错误数据 |

学习规则：

- 开启 TypeScript 的 `strict` 检查。
- 每个任务故意写一次错误，观察编译器能否发现。
- `as` 不会转换或校验数据；外部数据需要运行时检查。
- 做完模拟面板，再学 React，重做同一页面。

## 怎么判断学会了

每个任务都走一遍：先预测结果 → 动手写 → 检查或运行 → 解释原因 → 独立改需求。

能运行只是第一步。能解释关键代码，并在不看示例的情况下完成一次小修改，才勾选完成。

## 任务拆解

### 1. 消息列表 → `ts/9-message.ts`

1. 定义角色类型和消息类型，创建一条消息。
2. 故意拼错角色、漏写内容，观察类型错误并修复。
3. 创建消息数组，写添加函数，返回新数组。
4. 写筛选函数，只保留用户消息。
5. 独立改需求：筛选助手消息。

检查：能说明字面量联合为什么比 `string` 更适合角色，知道展开和 `filter` 是 JS 功能。

### 2. 任务状态 → `ts/10-task-state.ts`

1. 先写 `status: string`、`result?: string`、`error?: string`，构造一个没有结果的成功状态。
2. 改成联合类型：等待、运行、成功带结果、失败带错误。
3. 写 `describeTask`，按状态返回提示文字，观察分支中的字段提示。
4. 用 `never` 检查遗漏分支；新增取消状态，先观察报错，再补齐分支。

检查：能解释为什么不能在所有状态下直接读取 `result`。类型约束数据形状，状态转移规则仍需自己实现。

### 3. 读取 JSON → `ts/11-parse-result.ts`

1. 准备三个 JSON 字符串：`{"result":"你好"}`、`{}`、`{"result":123}`。
2. 把解析结果存为 `unknown`，尝试直接读取 `result`，观察类型错误。
3. 依次检查：是对象、不是 `null`、存在 `result`、其值是字符串。
4. 把检查提取成解析函数；用 `try/catch` 处理无效 JSON 和字段不合法。

检查：三个输入都能得到明确结果；能解释为什么 `as` 不能代替检查。

### 4. 通用结果 → `ts/12-result.ts`

1. 分别定义消息结果和任务结果：成功带数据，失败带错误。
2. 找到重复部分，提取 `Result<T>`。
3. 创建 `Result<Message[]>` 和 `Result<string>`，读取成功分支的数据。
4. 独立改需求：增加 `Result<number>`，不要修改 `Result<T>`。

检查：成功分支保留具体数据类型，失败分支不能访问成功数据；能解释 `T` 与 `any` 的区别。

### 5. 智能体配置 → `ts/13-agent-config.ts`

1. 定义 `AgentConfig`，包含 `name: string` 和 `temperature: number`。
2. 使用 `satisfies AgentConfig` 检查一个配置对象，故意拼错字段。
3. 使用 `keyof AgentConfig` 限定配置键，尝试传入不存在的键。
4. 用 `Partial<AgentConfig>` 表达部分更新，实现返回新配置的更新函数。

检查：更新一个字段时不用填写所有字段；新增配置字段后，不用手写第二份更新类型。

### 6. 网页面板 → `task/agent-panel/`

1. 先用 HTML 写输入框、提交按钮、状态和回复区域，CSS 只做简单排版。
2. 用 TS 获取页面元素，检查元素存在，并绑定提交事件。
3. 写返回 `Promise<string>` 的模拟请求，体验 `async/await`。
4. 请求期间显示运行状态并禁止重复提交；用 `try/catch/finally` 展示结果并恢复按钮。
5. 让模拟请求故意失败，检查页面能否恢复到可再次提交的状态。

检查：能解释 TS 的类型检查、JS 的异步行为、浏览器的 DOM 各自负责什么。此时需要把 TS 转为 JS，通过本地 HTTP 服务打开页面。

### 7. 接入 Python → 继续修改面板

1. 写清接口地址、请求字段、成功响应和错误响应，并与 Python 后端对齐。
2. 用 `fetch` 替换模拟请求，先检查 HTTP 状态，再读取响应。
3. 把外部数据当作 `unknown`，校验通过后再显示；本地联调时配置后端允许页面来源。
4. 分别检查正常回复、后端关闭、非成功 HTTP 状态、响应字段错误。

检查：能独立新增一个响应字段，并同时修改后端、前端类型、校验和显示。
